# Package bindings port to v1.38.0

## Source and preservation

- Upstream: `v1.38.0` (`10476370f6a57bdb551be328761eabbfa5d17f6c`).
- Package work checkpoint: `5394917`.
- Backup branch: `backup/package-bindings-before-v1.38.0`.
- Integration branch: `feature/package-bindings-v1.38.0`.
- Upstream history is merged, preserving the existing package commits.

## Integration decisions

The fork and upstream both used schema version 8 for different changes.
The fork's existing versions 8–11 keep their meaning. Before adding the
ownership column, migration 8→9 ensures package tables exist, allowing an
upstream v8 database (which has no package tables) to upgrade. Migration
11→12 performs upstream's orphaned `project_default_export_agents` cleanup.
Existing package bindings, artifact keys and ownership metadata are preserved.

Package import continues to call the unscoped `clone_repo_ref` entry point.
In v1.38.0 this delegates to `clone_repo_ref_scoped` with no subpath, so the
scanner still receives the full repository, including sibling plugin artifacts.
Single-skill installs retain upstream's sparse checkout optimization.

The native Claude upgrade, Codex generated marketplace/adoption, hook ownership
and project manifest behavior remain covered by the existing package tests.

## Running

Run `npm run tauri:dev` to test the integrated desktop app. Opening an existing
library upgrades its database to schema 12. Older fork binaries and stock
upstream v1.38.0 do not support that schema; use a pre-upgrade database backup
if reverting the application. The Git backup branch preserves source code,
not the user's runtime database.
